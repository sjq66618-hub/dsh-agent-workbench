# DSH 媒体插件：QQ 音乐 + 百度网盘双入口实施方案

> 版本：2026-10-22 修订版（同日按新决定改为双入口）。本文是设计与实施约束，不是已实现或已验收的功能清单。
> 本轮只优化方案，不安装插件、不修改 desktop profile、不操作音乐/网盘账号。
> 结论：原方案方向正确，但不宜按原稿直接实施。QQ 音乐与百度网盘在业务对象、失败模式和交互节奏上差异大，最终选择是 **两个独立侧栏入口 + 两个独立原生 React 主面板 + 单一 `@local/dsh-media-hub` 安装 bundle（内含两个独立懒加载 provider，共享 Host 业务服务）+ 隔离的后台执行进程**。

## 1. 评审结论与本轮决策

保留原方案的三个目标：嵌入 DSH 主区域、保留 Agent 工具、不修改 DSH 本体。改变实现方式，而不是先做两套临时网页再重写。入口形态按本轮新决定改为两个独立入口、两个独立主面板；该改动只涉及入口与 UI 组织，不改变单 bundle、共享 Host 服务和执行隔离。

| 原方案问题 | 修订决策 | 理由 |
|---|---|---|
| 将入口组织与安装包拆分绑定 | QQ 音乐、百度网盘各有独立侧栏入口与主面板；只安装一个 `@local/dsh-media-hub`，内部两个独立懒加载 provider | 业务差异通过独立交互体现；复用身份、审批、任务等基础设施，避免重复建设；账号与设置各放自身面板内 |
| iframe 先行，后续换 React | 原生 React 为正式路线；不以 iframe 为默认过渡层 | 避免双份路由、主题、通信、播放器生命周期和移动端适配返工 |
| 直接假定 Slot/工具示例能运行 | 以目标 DSH 版本的真实类型与最小加载试验为 Gate | 官网 master 文档不等于本机发行版；错误注册也可能影响启动 |
| capability 注入 HTML，被描述为能阻止本机其他进程 | 复用 DSH 认证与远程配对；资源租约限权；不承诺隔离同用户进程 | 页面能取得的长期 bearer 不是本机进程安全边界 |
| 所有请求携带自定义头，同时使用原生 SSE/音频标签 | JSON、事件流、音频流分别设计认证 | 原生 EventSource/媒体标签不能像 fetch 一样任意设置请求头 |
| `spawn(bdp.cmd)` + `--json` 即视为结构化 SDK | 固定已核验的 Node 入口、参数数组与输出适配器 | Windows `.cmd` 与普通可执行文件不同；JSON 外壳可能仍包含文本 |
| UI 弹确认框，Agent 返回 `confirmRequired` | 所有变更共用 Host 端真实审批门 | 对话中的“已确认”或前端布尔值不构成执行授权 |
| 关闭面板任务继续，但插件卸载/退出无定义 | 明确 UI、宿主和工作进程三种生命周期 | 不能把面板隐藏等同于应用退出后任务仍可可靠运行 |
| 一口气完成所有增删改查，固定验收数据与工期 | 先只读与播放，再下载、上传，最后分享/删除/移动 | 尽早交付有用功能，避免以账号当前数据或上游偶然可用作验收基准 |

“最优”限定为当前场景：Windows、已有 DSH 与壁纸/远程插件、希望手机可访问、已有 QQ MCP 和 bdp。若目标平台变化，应重新评估，不能声称存在不受约束的全局最优架构。

## 2. 已知事实、待核验项与停止条件

### 2.1 证据边界

| 项目 | 本轮结论 | 实施时要求 |
|---|---|---|
| `sidebar.panellist` + `main` | 官方 sidebar 文档确认全局导航项 id 对应 root `main` keyed 项；双入口需各自有独立 id 与对应 `main` 项，同一插件注册多项的细节待本机核验 | 在目标发行版核对 `register` 参数、声明生命周期和销毁行为，确认两个入口 id 各自打开自己的主面板；原稿 `name: 'qqmusic'` 不作为已验证范例 |
| `ctx.tools.register` | 官方当前工具契约包含参数校验、canonical output 和取消信号 | 核验本机版本；不能继续使用缺失输出声明的原稿简化样例 |
| `timeoutMs` | 官方当前工具文档称其是声明，执行期限需要对应策略或协作实现 | 适配器必须实际传递 AbortSignal、终止自己拥有的任务，不能只填字段 |
| QQ API 候选 | npm 维护者说明支持 Node/Electron 接入、扫码、音乐库等能力 | 发布存在不等于本账号的真实播放/扫码已验收；固定通过测试的版本与完整性摘要 |
| QQ 候选精确版本 | 已通过 npm registry 元数据确认 `@yakult-green-tea/qq-music-api@3.3.5` 与 `@sansenjian/qq-music-api@2.6.0` 均存在，并取得发布完整性字段 | 发布存在不等于运行兼容；首次实施仍须锁定依赖、核验导出与真实业务，不使用搜索缓存猜版本 |
| bdp | 已读取本机 `baiduwangpan-cli@1.6.0` 的入口与源码；`ls` 返回 `{path, raw}`，通用引擎封装丢弃退出码/stderr | 详见第 14.1 节；相关能力通过错误传播与格式契约 Gate 前不得上线 |
| `dsh-app:` | 用户曾反馈远程插件安装后无法进入 DSH；本轮未重新调查该故障根因 | 桌面协议、loopback 浏览器、已配对手机、未配对请求都要单独测试；不把历史推测写成已证实归因 |
| 原有 QQ MCP / bdp 登录 | 作为现有资产保留 | 不读取或迁移账号秘密来证明方案；实际复用需单独验证凭据格式与状态所有者 |

### 2.2 P0 必过的兼容性 Gate

1. 记录目标 DSH、Node、插件包、工具 SDK、bdp 版本与构建摘要，不通过更换 DSH 版本来掩盖问题。
2. 在隔离测试配置中验证两个独立侧栏入口各自能打开对应的 `main` 原生面板，重载/卸载能完整清理各自的注册，不能改写默认会话路由；单独停用一个 provider 时只移除它自己的入口。
3. UI 调用经已验证的 DSH Client/Host 通信接缝，不硬编码端口，不改全局 fetch/WebSocket，不通过 hostname 单独判定所有者身份。
4. 验证一个只读 Agent 工具的输入、输出声明、错误、取消与生命周期；核验桌面自带 SDK 的解析来源，避免在 profile 中安装另一份运行时核心包。
5. 核对 QQ 包的无副作用导入、扫码通道、会话存储注入与取消能力；核对 bdp 的真实入口和机器可读输出。
6. 验证目标手机链路能携带正确身份并访问**明确放行**的插件方法/事件；不能假定增加 `/media/*` 路由就会自动被现有远程通道代理。

任一 Gate 失败：停在测试环境，显示可诊断错误；不关闭认证、不改 DSH 本体、不往启动阶段增加补丁式全局拦截。

## 3. 正式架构与安装边界

```text
DSH Client：两个独立侧栏入口、两个独立主面板（同一 bundle 注册）
  ├─ 「QQ 音乐」入口 → QQ 音乐主面板：搜索、歌单、歌词、队列、账号与设置
  ├─ 「百度网盘」入口 → 百度网盘主面板：目录、文件、传输、账号与设置
  └─ 每个客户端会话常驻的 PlayerController / TransferStore（跨面板切换不停止）
          │ 已验证的 DSH transport，携带调用者与工作区上下文
DSH Host：MediaService（两个面板共用）
  ├─ 输入/输出 schema、身份、审批、幂等、日志脱敏
  ├─ MusicProvider（按需启动 QQ 工作进程）
  ├─ NetdiskProvider（按需调用已核验的 bdp Node 入口）
  └─ JobStore（单写者日志 + 原子快照）
          │
      QQ API / bdp 的现有能力
```

### 3.1 单 bundle、模块隔离，不做微服务平台

- 首版只安装一个 `@local/dsh-media-hub`，在同一 bundle 内注册两个侧栏入口与两个主面板；`musicEnabled`、`netdiskEnabled` 是独立开关，不是两个安装包。
- 两个 provider 接口独立、按需懒加载、独立错误边界。依赖缺失或上游失败时，对应面板显示诊断/重试状态；未登录时保留可进入的登录引导，不能隐藏入口造成登录死角。用户明确停用 provider 才隐藏其入口；另一个入口始终独立可用，不影响主会话或 DSH 启动。
- 两个面板共用 Host 的同一套业务服务（身份、审批、任务、存储）；共享服务不等于共享 UI 外壳，也不新增聚合入口。
- Host 注册轻量服务与工具；外部包导入、联网、账户探测和 CLI 启动均推迟到首次使用，设实际超时。
- QQ SDK 在受管子进程中运行；CLI 在自己拥有的子进程中运行。UI ErrorBoundary 不能替代进程隔离。
- 不引入 Redis、数据库服务器、通用工作流平台或第三个 hub bundle。低并发传输使用单写者本地 journal；将来有规模证据再换持久队列。
- DSH/React 等宿主共享依赖按目标发行版的插件约定 externalize；不把另一份 DSH 核心 SDK 塞入 profile。

建议目录：

```text
<repo>\media-plugins\media-hub\
  package.json / cordis.patch.yml
  src\client\        导航、面板、常驻播放器、主题与手机布局
  src\host\          transport 适配、身份与审批、任务与存储
  src\providers\     music / netdisk 的统一契约与实现
  src\workers\       QQ 执行入口与受管进程协议
  src\contracts\     输入输出、能力、错误和事件 schema
  test\              离线契约、UI、生命周期、路径与权限回归
  scripts\           构建、测试安装、完整性验证、回滚
  lib\               可复现构建产物
```

状态目录由实际 DSH profile 数据根与账号标识派生，**不得写死共享 `$DSH_HOME/media`**。测试配置有独立存储根，不能因为复制 profile 就共享生产插件状态、队列或新登录态。

### 3.2 UI 取舍

- 侧栏两个独立入口（「QQ 音乐」「百度网盘」），各自打开独立主面板；不设聚合式“媒体中心”入口，也不在主区域内用两个页签承载两套业务。
- 账号、服务状态与设置分别放在各自面板内，不新增两个全局设置栏位；两个面板共享 Host 服务，但各自持有自己的入口与 UI 外壳。
- 停用某 provider 只隐藏或禁用其自己的入口，另一个照常使用；不留空白主面板，也不留悬空导航项。
- 正式实现使用宿主的 React 与主题 token，组件样式以插件根类命名空间限定；不改全局 body、会话 CSS 或背景层。
- 手机小屏：音乐采用列表/详情切换；网盘表格降为可操作行，面包屑可滚动，上传使用手机文件选择器。
- 不用外站 iframe 冒充“嵌入 QQ/网盘”；也不宣称同源 iframe 提供了安全隔离。确需第三方页面时另行验证 CSP、来源与主题桥，作为明确降级，不成为主路线。
- 在两个主面板之间切换、会话切换、侧栏收起后音乐继续播放；只有停止播放、注销、插件停用或客户端关闭时释放音频资源。
- 单独停用音乐 provider 时停止其播放并释放资源；单独停用网盘 provider 不影响播放。卸载整个 bundle 才同时撤销两个入口与对应服务，不能把两个入口写成两个可独立卸载的安装包。
- 每个连接端独立播放：手机点播放默认在手机响，电脑点播放默认在电脑响。首版不隐式控制另一台设备，也不宣称后台/锁屏播放在所有手机上可靠。

## 4. 一份业务能力，同时服务 UI 和 Agent

UI 与工具必须调用同一个 Host 业务服务，不能各自拼 HTTP、CLI 命令与重试规则。

业务对象使用稳定标识：`songMid`、`remoteFileId`、`remotePath`、`jobId`、`workspaceId`。不把 CLI 原始文本、QQ Cookie、临时播放地址作为主业务模型。

统一失败结构：`{ code, message, retryable, requestId }`；长任务返回 `{ jobId, state }`，详情通过订阅/查询读取。典型错误：`AUTH_REQUIRED`、`FORBIDDEN`、`APPROVAL_REQUIRED`、`UPSTREAM_UNAVAILABLE`、`UNPLAYABLE`、`INVALID_PATH`、`CONFLICT`、`DISK_FULL`、`ABORTED`、`UNSUPPORTED_CAPABILITY`。

### 4.1 工具范围

| 阶段 | 音乐 | 网盘 |
|---|---|---|
| 首个可用版本 | 搜索、曲目信息、歌词、歌单；播放须有明确客户端目标 | 账号状态摘要、列目录、搜索、文件元信息、配额 |
| 传输阶段 | 播放队列与播放器命令（目标客户端在线才可执行） | 下载到绑定工作区、查询/取消本人任务；上传经本地文件授权或上传会话 |
| 变更阶段 | 账号相关变更另做能力与审批评估 | 创建目录、分享、删除、移动、覆盖，均经统一审批 |

- 不同时向 Agent 暴露两组含义重复、名字近似的 QQ MCP 与原生工具；保留旧配置，但当前配置选择一组为主要实现。
- 外部 MCP 不在同一 Host 中再套一层“启动 server → SDK 调自己”。MCP 如需保留，应做同一业务契约的独立入口或显式故障切换。
- 返回搜索结果默认截断并分页；歌词与大目录按需读取，不一次把整个歌单/全盘文件塞进上下文。
- 默认不提供把带凭据播放 URL直接交给模型的工具；需要播放时返回客户端可使用的短期资源句柄和授权状态。
- 工具没有面板也能完成只读业务；播放有 UI/设备依赖时返回明确状态，不能伪造“已在电脑播放”。

## 5. QQ 音乐：先做可靠播放，再扩展账号能力

### 5.1 选型决策

首选核验 `@yakult-green-tea/qq-music-api@3.3.5`：维护者文档列有原生扫码、会话仓库注入与 Node/Electron 嵌入能力，与本项目更匹配。`@sansenjian/qq-music-api@2.6.0` 作为兼容备选，现有 MCP 是可参考资产，不是自动共享登录的证明。

registry 元数据已确认前者要求 Node `>=20`、公开 `./serverless` 入口；后者声明 Node `^20.17.0 || >=22.9.0`、公开 `./sdk` 与 `./app` 入口。P0 优先验证各自的无监听 SDK/serverless 入口；不能仅凭入口名称就假定无副作用，也不能用“DSH 带 Node”代替具体 runtime 兼容测试。

P0 用**同一组能力用例**比较候选，不以“各跑 30 分钟”作为验收标准：搜索 → 详情 → 歌词 → 授权播放 → 歌单 → 登录通道查询 → 二维码过期/取消 → 重启恢复。版本、导出方式和落盘副作用核验后才锁定；不在运行中自动升级上游包。

采用 worker 内嵌 SDK/serverless 入口；若特定能力仅能通过 app handler 使用，再在 worker 中适配。是否需要额外 loopback 监听由 P0 结果决定，默认不开放固定 3200 端口，不让其启动副作用污染 DSH Host。

### 5.2 账号与播放语义

- UI 只获得二维码、登录阶段、过期时间和账号摘要；会话密钥由 Host/worker 控制。
- 持久 QQ 会话使用可注入的受保护存储；Windows 采用操作系统保护的凭据方案。无法提供受保护后端时退为会话内登录，不默认明文保存 Cookie。
- 原 MCP 与新 provider 只有在存储接口与格式明确兼容时才能复用登录；否则一次显式迁移或重新扫码。禁止两个进程同时改同一状态文件。
- 保存曲目 id、队列和播放位置，不保存已签名播放地址；播放前按当前账号和权限重新解析。
- 正确区分完整可播、试听、账号权限不足、版权区域限制和暂时失败；取到链接不等于承诺全曲可播。
- 播放地址获取失败不得自动切换到另一账号，也不得显示虚假“最高无损”。先验证浏览器/Electron实际能解码的格式。
- 直接音频源与本地转发流由 P0 实测选择。若必须转发，提供真实 Range/HEAD/取消支持、流式背压、受限上游目标和请求上限，不做任意 URL 代理、不整曲缓存到内存或磁盘。
- 搜索 debounce、按账号隔离的有界缓存；注销清理该账号的会话与缓存，停止其播放，不清除其他 provider。

## 6. 百度网盘：CLI 是适配对象，不等于稳定 SDK

### 6.1 执行契约

- 复用本机 bdp 的固定版本和原登录上下文，不复制、打印或重新保存其 secret；必须分别识别 Web 凭据存在、PCS 引擎会话和真实请求有效性，不能把 `whoami.loggedIn` 当在线认证成功。
- Windows 的 Node CLI 启动使用固定 Node 可执行文件 + 实际 JS 入口 + 参数数组；`shell: false`、`windowsHide: true`，显式 `cwd`、受控环境、超时与输出上限。不能直接用 Electron 的 `process.execPath` 假装 Node；需核验 DSH 提供的 worker runtime 或固定的独立 Node。
- 不把用户输入拼进 `cmd /c` 或 PowerShell 字符串，不把 `.cmd` 当普通可执行文件直接 spawn。
- 固定子命令与 flag 白名单；参数数组仍需防选项注入。远端路径规范化为绝对网盘路径，本地路径为已授权的绝对路径；只有目标 parser 确认支持时才使用 `--` 分隔符，不让模型传原始命令片段。
- 每个子命令单独验证参数和返回值。`--json` 必须做形状校验；如果其中 `data` 仍是终端文本，不宣称已经得到结构化目录。
- 本机 1.6.0 的 `runPCS` 丢弃引擎退出码/stderr，且 `ls/search/put/rm/mkdir` 依赖该封装；外层补一个 `try/catch` 或检查 exit 0 无法补回丢失的证据。**首选在插件 worker 内提供小型、受版本约束的 PCS runner**，用经过 P0 核验的引擎绝对路径、子命令与原会话上下文直接收集 `exitCode/stdout/stderr`；不改全局 bdp 包、不重写百度协议、不注入其全局 `child_process`。已具备可靠结果的 bdp Node 子命令可继续复用，均由一个 NetdiskProvider 归一化；写操作禁止静默切换执行后端。
- 引擎 runner 也不自动等于结构化 SDK。按固定引擎版本保存脱敏 fixture，明确无歧义字段和无法支持的文件名；不能用空格分隔解析中文/带空格文件名。若只能得到有歧义的文本，保持显式错误/受限能力，不靠猜测还原，不把解析失败显示为“空目录”。
- `raw === ''` 既不能直接判为空目录，也不能直接判为请求失败；必须结合可信退出状态、认证探测与对象元信息。写操作只有取得可信成功证据并完成必要回读才标 `succeeded`，否则 `failed` 或 `unknown_outcome`。
- 登录失效返回 `AUTH_REQUIRED`，提示在受信任桌面端完成原 CLI 登录；首版不强行把 CLI 的交互式扫码流程塞入 DSH。
- 不调用会返回完整配置的 `bdp config --json`。子进程结果进入业务层前按 schema 白名单投影，移除 Cookie、临时直链、完整 raw 和不必要的本机路径；不能只在 UI 隐藏后仍把 canonical tool value 交给程序调用者。
- 非交互模式、退出码、stdout/stderr、超时、取消和失败后的不确定结果必须归一化。仅有控制台进度文案时显示“进行中”，不伪造百分比。
- `get --progress` 的文本进度仅在固定版本 parser 通过 fixture 后启用，上传无可靠进度源时显示不定进度；不能用计时器生成百分比。`--resume` 标志存在也不证明任意引擎/分块/取消场景可恢复。

### 6.2 文件与工作区

- Agent 调用必须捕获该次调用所属工作区；不使用全局活动窗口、最后一次点击的目录或 `process.cwd()` 代替。
- 从全局网盘面板发起下载时，用户先选择目标工作区。远程手机选择的是电脑上的已授权工作区，不是手机文件系统。
- 默认输出 `工作区\downloads\任务子目录`，临时数据写同工作区的受管 staging 目录；校验后原子提交，不默认覆盖现有文件。
- 上传分两条明确路径：桌面受授权的本地文件句柄；手机浏览器创建的流式上传会话。不能把手机传来的 `C:\...` 当成电脑任意文件读取权限。
- 用规范化、realpath/父目录验证、Windows 大小写/盘符与 junction/symlink 测试限制边界；不以字符串 `startsWith(workspace)` 判断归属。写入/提交前重新校验受管父目录，避免检查后被替换的 junction；如当前实现不能消除竞态，就拒绝可重解析的目标链，不宣称一次 realpath 已解决全部路径问题。
- 文件名验证考虑保留名、路径分隔符、尾点/尾空格和冲突；远端路径与本地路径使用不同类型，不互相拼接。
- 上传走有上限的流式 staging，检查大小、磁盘余量、会话所有者与过期；只清理自己登记的临时文件，不递归删除用户目录。

### 6.3 先读与下载，后写与分享

首个可用版只承诺目录/搜索/元信息/配额。下载能力先测临时工作区；上传、覆盖、移动、删除与分享在审批机制通过后逐项开放。

分享会扩大可见范围，不因“不修改文件”而归为只读。删除/移动/覆盖还要在执行前重新核对文件标识与版本；对象变化就要求重新审批。

## 7. 身份、审批与跨端传输

### 7.1 请求身份与资源认证

| 调用来源 | 身份来源 | 默认权限 |
|---|---|---|
| 原生桌面 `dsh-app:` | 宿主已经认证的桌面桥与 Host 身份上下文 | 按业务权限；协议识别只负责兼容性，不单独授予 Host 权限 |
| 本机浏览器 | DSH 原有登录/所有者会话和请求来源校验 | 按业务权限，不因 socket 为 127/8 就绕过认证 |
| 已配对手机 | 已有远程网关验证的设备身份及当前会话 | 只开放列明的插件方法，写操作仍需审批 |
| Agent 工具 | DSH 调用身份、会话、工作区与工具权限策略 | 与 UI 共用 Host 操作检查 |
| 未认证/未配对请求 | 无 | 拒绝；失败不能反过来遮住桌面主界面 |

- JSON 请求优先走 SDK transport。自定义 HTTP 如确有必要，仅注册明确前缀、方法、schema、大小限制和鉴权，拒绝宽泛 CORS。
- 长期 Cookie/token 不注入 HTML、URL、localStorage 或模型上下文，不把错误信息当成可展示凭据。
- 事件流优先复用已有认证订阅；否则使用 fetch 流或带现有会话的连接。原生 `EventSource` 不能被要求携带任意 `x-media-token`。
- 音频标签不能任意加鉴权头：优先使用已认证的媒体流；必要时使用只绑定单一曲目、客户端、GET/HEAD 和到期时间的短期资源租约。短期资源句柄不是通用 API bearer，日志需脱敏且支持注销撤销。
- “绑定客户端”必须由服务端核验现有会话才能成立；若媒体请求只能携带租约 URL，该 URL 仍是短期 bearer，可被转用，不能宣传为设备不可转移凭证。此时最小化权限/有效期、限制来源与并发，不扩展到普通业务 API。
- 同用户本机进程读取同用户文件不在此插件可保证的隔离范围内。token、Origin 和 CSP 都不能被描述成能防住任意本机进程。

### 7.2 真正生效的操作确认

Host 每个变更方法都做最终权限与审批校验。工具侧对接目标版本的审批服务，`tools/pre-execute` 负责 ask 流程；如果目标版本支持 `ctx.tools.guard`，用其不可被后续监听器放宽的拒绝机制补强，而不把可重排的单一事件监听器当最终权限边界。接缝不可用时，首版不注册写入型 Agent 工具，不能用提示词代替门禁。

流程：创建待审批意图 → 向真实用户显示影响范围 → 可信 UI 或 DSH 原生审批确认 → Host 再执行。审批绑定调用者、账号、操作、规范化对象、目标工作区、参数摘要和有效期，单次使用；参数/对象变化即失效。

`confirmed: true`、重复发送同一请求、模型自行填写 `confirmToken` 或在对话中声称“用户同意”均不绕过审批。UI 按钮和 Agent 工具必须走同一审批与幂等服务。

## 8. 后台任务与生命周期

状态至少包含：`queued`、`awaiting_approval`、`running`、`cancelling`、`succeeded`、`failed`、`cancelled`、`interrupted`、`unknown_outcome`。记录账号引用、所有者、绑定工作区、幂等键、实际字节数与错误码，不记录账户秘密。

- 下载并发初值 2、上传并发初值 1，是产品默认值，不是上游能力证明；任务队列有上限。
- 任务先持久化再启动；进度合并/节流后通知，关闭面板只取消订阅，不取消传输。
- 取消仅终止该任务拥有的进程树，并等待其退出；不按程序名批量杀进程。处理 Windows 子进程树残留与取消后临时文件清理。
- 插件停用/DSH退出时限时排空或停止 worker，记录中断。下次启动标记 `interrupted`；仅对已经证明支持断点续传且源对象未变的任务提供恢复，不承诺自动无损续传。
- 只读瞬时错误可有限退避重试。分享、删除、覆盖等变更操作不盲目重试；服务端成功但本地超时的情况进入 `unknown_outcome`，先查询核实。
- 重复点击/网络重发用幂等键避免重复任务；设备不能查询或取消另一身份的 job。
- 首版 journal 使用单写者追加记录与原子快照；崩溃恢复忽略不完整尾记录。账号密钥不写 journal。若复用 DSH jobs 服务，先证明其持久性、事件和跨端所有者契约，而不是只看到同名 API 就替代。

## 10. 验收矩阵：不是看见图标就算集成完成

1. **DSH 稳定性**：冷启动、热重载、依赖缺失、上游离线、单 provider 抛错、启停循环；仍能进入原会话和输入框；无顶层未捕获拒绝。
2. **现有插件回归**：WE 壁纸、启动动画、工坊、远程插件、主会话与草稿；只检查是否退化，不修改用户偏好。
3. **Slot 生命周期**：宿主槽位晚到、卸载、恢复；两个入口各自注册一次且无重复注册。单独停用 provider 只移除自身入口与面板，当前选中项失效时回退到有效主面板，另一入口仍可使用；卸载整个 bundle 才移除两组注册。未登录保留登录引导，不新增全局设置栏位。
4. **工具契约**：参数与输出 schema、分页、错误码、取消、真实截止时间；不靠未加载的 timeout 策略兜底。
5. **账号**：未登录、二维码过期/取消、凭据失效、重启恢复、两端同时连接；不以拷贝文件假定会话兼容。
6. **播放**：有权/试听/无权样本；不固定某首歌必可播；暂停/seek/切歌、主面板切换/仅 UI 卸载不中断、停用网盘不中断、停用音乐停止播放、设备目标、媒体租约与断网。
7. **文件解析**：空目录与引擎失败不能混淆；覆盖退出码异常、exit 0 含错误、空 raw、输出截断、字段漂移、中文/空格/特殊字符、无修改时间、异常配额。不写死“根目录 7 项”等账号数据；上游无分页时采用有界快照和 UI 分页，不谎称服务端分页或无限全盘搜索。
8. **路径边界**：`..`、相邻前缀目录、盘符切换、UNC、junction/symlink、保留文件名、已存在文件；默认不覆盖、不越界。
9. **任务**：重复点击、取消中、进程卡住、超过 4 GiB 的离线流式测试、进度无总量、网络重连、宿主退出、结果不确定。
10. **权限**：未配对访问、过期/撤销设备、跨账号缓存、跨 job 查询、伪造确认、审批重放、文件对象变化、CSRF/Origin 与 SSRF。
11. **手机**：同一 DSH 实例的列表、歌词、任务进度、手机上传、电脑工作区下载；明确音频在哪台设备播放。
12. **发布**：依赖锁文件、构建与部署摘要、备份、单命令禁用/回滚、卸载后无监听/子进程/定时器残留。

离线自动测试与真实服务验收分开记录；真实账号、手机真机、QQ授权播放、网盘传输未执行时必须标为“未执行”，不得由 mock 通过推导为已可用。

## 11. 生产安装、回滚与资产复用

- 测试配置使用独立端口和插件数据根；如需复制现有 profile，只读留存原始清单，避免并发进程写同一配置或账号仓库。
- 桌面不停机时不改生产包；投产前备份当前配置、插件清单与文件摘要，只增加此 bundle，不顺带升级其他插件。
- 候选构建经相同版本测试后原子部署；注意 pnpm hardlink，不原地改共享包内容。
- 回滚先停止此插件任务，让当前选中的媒体面板退回有效主面板，再移除本 bundle 的两组注册；只恢复本次改动，不把旧备份覆盖后来用户更改的壁纸/聊天/全局配置。
- 既有 QQ MCP、百度 skill 和 bdp 登录都保留。实际功能验证成功后再决定隐藏重复工具，不提前删除旧入口。
- 本轮不接管远程插件、壁纸中心或 DSH 主路由；远程身份适配通过公开接缝完成。无法通过时明确列为兼容性阻塞，不加全局 monkey patch。
