# DSH 个人工具插件计划（远程控制 / QQ 音乐 / 百度网盘）

> 方向已定：QQ、微信只做 **IM → DSH 远程控制**，不碰个人账号；QQ 音乐、百度网盘自研插件。
> 原则：现成插件先隔离试驾，通过再进主 profile；自研插件先工具、后 UI。

## 1. 目标与非目标

**目标**

- 手机 QQ / 微信里给机器人发消息，远程驱动电脑上的 DSH：发任务、收流式回复、远程审批、收发文件。
- DSH 里有 QQ 音乐工具 + 播放器面板：搜歌、歌单、播放链接、歌词、队列。
- DSH 里有百度网盘工具 + 文件面板：列表、搜索、下载、上传、分享（危险操作二次确认）。

**非目标**

- 不接管个人 QQ/微信账号，不做个人聊天记录读取，不做群发/营销。
- 不做 QQ 音乐/网盘账号共享，不绕过 VIP/DRM。
- 不在本轮做“统一壁纸中心”那类视觉整合。

## 2. 现成插件候选（远程控制）

## 2.5 把方案 2 的多功能并入方案 1（可行）

先给结论：**能，`@michengai/dsh-im-connect` 是 Apache-2.0，允许 fork/修改**；而且它本身已经覆盖了大部分能力，真正缺的主要是微信侧的“精细化”功能。

### 能力对比（谁有什么）

| 能力 | im-connect | qqbot-bridge | dsh-wechat | 合并动作 |
|---|---|---|---|---|
| QQ 官方 Bot 单聊 | ✅ | ✅ | — | 保留 |
| 微信 iLink | ✅ | — | ✅ | 保留 |
| 审批 / 提问转发 | ✅（5 分钟超时） | ✅（300s fail-closed） | ✅（两端同弹） | 保留，核对超时语义 |
| 文件 / 图片收发 | ✅（4 个/20MiB） | ✅（send_file/send_image） | ✅ | 保留 |
| 每账号工作区/模型/权限 | ✅ | 部分 | ✅ | 保留 |
| 多平台（9 个） | ✅ | — | — | 保留 |
| 命令菜单/分页 | ✅（/menu、/sessions…） | ✅（9 命令+翻页） | ✅（更细） | 保留 |
| 分步流式输出 | 部分 | ✅（每 step 一条） | ✅ | **补** |
| 语音消息 | ❌ | — | ✅ | **补**（看 iLink API） |
| `/at` 引用会话/文件合并 | ❌ | — | ✅ | **补** |
| 静默/结论/`/flush` | ❌ | — | ✅ | **补** |
| 秘密脱敏 / 审计 / 文件范围 | 部分 | — | ✅ | **补** |
| 入站白名单/私聊准入 | 部分 | — | ✅ | **补** |

### 合并方式：fork 增强，而不是重写

1. 建 `@local/dsh-im-connect-plus`，基于 `@michengai/dsh-im-connect@1.0.12` fork，保留 Apache-2.0 声明与上游出处。
2. 所有新能力用配置开关包起来，默认关闭，避免影响现有 8 个平台。
3. 合并顺序（按风险从低到高）：
   - P1 安全：秘密脱敏、审计日志、入站白名单、文件范围限制；
   - P2 推送：静默模式、结论模式、`/flush`、长消息分片；
   - P3 引用：`/at` 会话/文件合并；
   - P4 流式：每 step 一条、Markdown 渲染（按平台能力降级）；
   - P5 语音：仅微信 iLink 支持时启用。
4. 测试：`imtest` profile，QQ Bot 沙箱 + 微信/企微；每个开关单独回归。
5. 维护：钉住上游 commit，每季度 rebase 一次；能上游 PR 就上游。

**工作量**：安全+推送+引用约 2-3 天；流式 1 天；语音 1-2 天（取决于 iLink 是否给语音接口）。总计 **4-6 天**，不含账号审核等待。

**风险**：fork 会随上游快速迭代产生冲突；语音能力受平台限制；微信 iLink 的账号/接口准入不确定。

## 2.6 凭据准备（现在两样都没有）

| 通道 | 需要什么 | 路径 | 备注 |
|---|---|---|---|
| QQ 官方 Bot | AppID + AppSecret，C2C 私聊权限，测试用户 | q.qq.com 开放平台 → 创建机器人 → 沙箱/测试 → 提交审核 | 审核通过前只能沙箱测试；个人开发者可注册 |
| 微信 iLink | 专用微信号 + iLink 接入资格 + 扫码 | 按 im-connect 文档/服务方指引 | **不确定个人能否开通**；开通不了就换企微 |
| 企业微信（备选） | 企微智能机器人 Bot ID/Secret 或扫码 | 企业微信后台 → 智能机器人 | 官方、稳定、比 iLink 好申请；im-connect 支持 |

**建议**：QQ Bot 先注册；微信侧优先确认 iLink 能否开通，开不了就用**企业微信**，不碰个人微信协议。



### 3.1 QQ 音乐插件：可以

- 数据层：`@yakult-green-tea/qq-music-api` 3.3.5（扫码登录、个人库、播放链接）或 `@sansenjian/qq-music-api` 2.6.0 + MCP。
- Host 半：搜索、歌曲详情、播放链接、歌词、歌单、登录状态/二维码。
- Client 半：右侧栏「音乐」面板（搜索框、结果、队列、播放/暂停、进度、歌词），音频用 `<audio>` 播放。
- 登录：扫码或 cookie；VIP/版权曲目的播放链接可能受账号权限限制，失败要明确提示而不是静默。
- 现状：MCP 已经挂进「工坊·主控」，9 个工具可用；自研插件是在它之上补 UI 和更顺手的工具名。

### 3.2 百度网盘插件：可以

- 数据层：`baiduwangpan-cli` 1.6.0（Agent 友好，全盘读写、免下载读文件）优先；长期可切 OpenList HTTP API。
- Host 半：`baidu_ls`、`baidu_search`、`baidu_download`、`baidu_upload`、`baidu_share`、`baidu_status`。
- Client 半：可选文件浏览面板；第一版可以只做工具。
- 权限：只读默认；上传/覆盖/删除/分享必须二次确认；下载落到工作区 `downloads/` 并限制大小。
- 登录：扫码或 BDUSS cookie；cookie 失效要提示重新登录，不做自动重试轰炸。

## 4. 架构

```
DSH desktop profile
├─ @michengai/dsh-im-connect (QQ/微信 → DSH)
│  ├─ 账号/权限/工作区映射
│  ├─ 审批/提问转发
│  └─ 文件/图片收发
├─ @local/dsh-qqmusic (自研)
│  ├─ host: QQMusicApi 适配器 + tools + 登录/缓存
│  └─ client: 音乐面板
├─ @local/dsh-baidu-netdisk (自研)
│  ├─ host: baiduwangpan-cli 适配器 + tools
│  └─ client: 文件面板（二期）
└─ @local/dsh-personal-hub (可选，二期)
   └─ 一个「个人工具」页，三个标签：远程控制状态 / 音乐 / 网盘
```

## 5. 分阶段计划

### P0 决策与准备（0.5 天）

- 选 IM 插件路线（im-connect 还是 qqbot-bridge + dsh-wechat）。
- 准备 QQ 开放平台机器人 AppID/Secret；准备微信 iLink 专用账号（扫码）。
- 备份 profile；建测试 profile `imtest`。

**验收**：账号/凭据齐备，路线确定。

### P1 远程控制（1-2 天）

1. 测试 profile 安装 `@michengai/dsh-im-connect`（钉版本），启动无报错。
2. 配置 QQ Bot（AppID/Secret）与微信 iLink 扫码；各发一条私聊消息。
3. 验证：任务下发、流式回复、审批卡、选择题、文件回传、`/switch` 工作区。
4. 通过后装进 desktop；配置 allowlist、私聊审批、秘密脱敏、审计。
5. 优化项（按需）：
   - 每个 IM 账号绑定 `wb-main` preset 与固定工作区；
   - 长消息分片、Markdown、图片/文件大小限制；
   - 断线重连/心跳/去重；
   - 速率限制与失败回执；
   - 设置页中文文案与帮助命令。

**验收**：手机 QQ 和微信各完成一次「发任务 → 收结果 → 审批 → 收文件」。

### P2 QQ 音乐自研插件（2-3 天）

1. 先补 MCP 的缺口：扫码登录、播放链接、歌词（用 `qq_music_auth_status`/`qq_music_call_api` 验证）。
2. 建 `@local/dsh-qqmusic` host 插件：tools + 登录/缓存 + 错误码。
3. 建 client 面板：搜索/队列/播放/歌词；`<audio>` 播放。
4. 验收：搜「晴天」→ 取播放链接 → 面板可播 → 歌词同步。

**风险**：VIP/版权曲目播放链接受限；API 变更；不要缓存完整音频。

### P3 百度网盘自研插件（2-3 天）

1. 先包 CLI skill（`baidu-netdisk`）跑通 `ls/search/download`。
2. 建 `@local/dsh-baidu-netdisk` host 插件：tools + 凭据 + 下载任务。
3. 上传/分享加二次确认与大小限制；文件面板二期。
4. 验收：列出目录、搜文件、下载一个小文件到工作区。

**风险**：账号限速/风控；cookie 失效；大文件占磁盘。

### P4 个人工具中心（1-2 天，可选）

- 一个设置页/侧栏页，三个标签：远程控制状态、音乐、网盘。
- 第三方 IM 插件的设置页仍是它自己的；我们只做状态汇总与入口，不重复实现。

## 6. 验收标准汇总

| 工作流 | 验收 |
|---|---|
| QQ 远程 | 手机 QQ 私聊 bot：发任务、收流式回复、远程审批、收文件 |
| 微信远程 | 微信 iLink 私聊：同上；语音/图片至少一项可用 |
| QQ 音乐 | 搜歌、播放链接、歌词、面板播放 |
| 百度网盘 | 列表、搜索、下载小文件、上传（确认后） |
| 稳定性 | 重启 DSH 后配置不丢；断线能重连；失败有明确回执 |

## 7. 风险与对策

| 风险 | 对策 |
|---|---|
| QQ Bot 审核/权限限制 | 先用测试机器人 + 测试用户；确认单聊权限再推广 |
| 微信 iLink 账号风险 | 专用账号；只私聊；限频；随时可停 |
| 第三方插件供应链 | 钉版本、隔离 profile 试驾、备份、失败回滚 |
| 音乐版权/VIP | 只取用户账号有权播放的链接；失败明确提示 |
| 网盘风控/限速 | 只读优先；下载走后台 job；错误码透传 |
| 设置页膨胀 | 二期做「个人工具中心」；一期接受插件自带设置页 |
