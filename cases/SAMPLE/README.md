# SAMPLE — 分析案例目录模板

复制本目录作为新案例的骨架，命名用 `cases/<日期>-<对象>-<动作>/`，例如 `cases/20261023-lab-router-firmware/`。

## 目录约定

| 文件 | 内容 |
|---|---|
| `README.md` | 案例目标、授权来源、范围、时间线、结论 |
| `evidence/` | 命令输出、截图、日志原文（不改写、不截断关键行） |
| `artifacts/` | 提取物、样本副本、生成的脚本（**只放副本，不动原件**） |
| `notes.md` | 过程中的假设、试过没用的路子、待验证项 |

## 三条底线

1. **只碰自有或已授权目标。** 授权来源写进 `README.md`，没有就不开工。
2. **原件只读。** 样本先哈希再复制，分析只在副本上做。
3. **证据优先。** 结论要能指到「文件:行」或命令输出；没跑过的写「未验证」。

## 交付

案例完成后 `README.md` 收敛为可复现的步骤序列：环境、命令、预期输出、实际输出。别人照着能跑出同样结果才算交付。
